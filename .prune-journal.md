Discoveries that make future pruning faster. Not a work log.

## 2026-09-03 - SessionModel selectors duplicate derive.ts

**Learning:**
`web/src/lib/session/model.ts` grew query methods (`agents`, `rollup`, `counts`,
`tabHasBlocked`) plus a trivial `statusWord` that duplicated the pure selectors in
`web/src/lib/session/derive.ts` (`agentsOf`, `rollupOf`, `countsOf`,
`tabHasBlocked`). The UI and tests use the derive.ts versions exclusively;
`store.ts` never exposes the model instance to components, so the model methods
were unreachable dead duplicates. okf `frontend/session-store.md` documents
derive.ts as the selector home — the executable + doc truth both point there.

**Protected (do NOT prune):** the SessionModel *delta handlers* in `apply()`
(`workspace.updated`, `tab.updated`, `pane.updated`, `pane.agent_status_changed`,
`pane.output_matched`) look dead because the Go backend currently re-broadcasts
full snapshots (see `docs/ARCHITECTURE_RECOMMENDATIONS.md` §2.2 line 101), but
they are spec-required (`docs/IMPLEMENTATION_PROMPT.md` live-patch list) and
kept deliberately. `space()` and `findPane()` are live internal callers of
`apply()`.

**Action:**
Deleted the four unused query methods + `statusWord`; cleaned now-unused imports
(`STATUS_ORDER`, `Rollup`, `Status`). If future selector logic is needed, add it
to derive.ts, not the model.
